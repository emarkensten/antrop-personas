# Audit report structure

The polished docx report is delivered to the client. Its job is to be defensible: every finding traces to a source, every recommendation is severity-ranked.

## Sections, in order

### 1. Executive summary
~200 words. Three things:
1. Where the archetypes hold up well — name the strongest 1–2 archetypes and the strongest claims
2. Where they are weakest — name the 2–3 most consequential weaknesses
3. The single most important caveat — the one thing the reader should remember if they read nothing else

Do not bury bad news here. The audit's value is showing what's wrong, not signing off.

### 2. Method
Brief. The seven checks, named, with a one-line description of how each was operationalised. Reference `references/seven-checks-quickref.md` if available.

### 3. Per-archetype findings
For each archetype:

**3.X · <Archetype name>**

- **Traceability table** — claim / verdict / evidence. Three columns. Verdict colour-coded (GROUNDED green, THIN amber, OVER-REACH/UNGROUNDED red, MILDLY EDITED amber).
- **Verbatim quote integrity** — every attributed quote with verdict (VERIFIED / MILDLY EDITED / MINOR PARAPHRASE / FABRICATED). Surface paraphrases explicitly — the audit's reader needs to know what was rewritten.
- **Negative case analysis** — contradicting evidence found in composite members' interviews, with verbatim quotes.
- **Composite coherence** — variance within the composite that the archetype smooths over, with examples.

### 4. Cross-cutting findings

**Coverage and orphan material.** Per-participant fit summary (good / partial / loose). Then the most significant sample-wide orphans — material in the data no archetype represents — ranked by strategic cost.

**Distinctiveness.** Pairs of archetypes at risk of collapsing, checked. Differences either confirmed or downgraded.

**Triangulation against the thematic analysis.** Theme-anchor accuracy. Themes that no archetype represents. Three-voice differentiation preserved or collapsed?

**Saturation.** Did new themes still emerge in the last 2–3 interviews?

### 5. Recommendations — severity ranked

A table: priority (HIGH / MEDIUM / LOW) / recommendation / why. Order by priority. HIGH at the top. The audit's whole reason for existing is to surface these.

### 6. Limitations of this audit

The honest list: single-rater, no blind sort, no member checking, no external triangulation, treats themes as reliable intermediate. The reader should know what wasn't checked.

## Visual + format

- Use the docx skill to produce the polished version
- Tables for traceability (3 cols) and recommendations (3 cols) — colour-coded by verdict / priority
- Section headings in blue or dark teal (matches Antrop)
- Body text in Calibri or similar — readable, not designed
- Quotes inline as block quotes with interview-id attribution

The audit report is not a designed deliverable. It is a working document for the client. Readability over polish.
